//MIDDLEWARES and ROUTE----->

app.use() is how you register middleware in Express. Middleware is a function that runs on incoming
requests before they reach your route handlers.
A middleware function receives (req, res, next). It can:

read or modify req and res
end the request by sending a response
call next() to hand off to the next function in the chain

A route is a rule that says "when a request comes in with this HTTP method and this path, run this function."
A route has three parts: the method (get, post, put, delete), the path (/users), and the handler (the function that sends the response).

Router

A router is a mini-app that holds a group of related routes,
so you don't put everything in one file. It's created with express.Router().

//MONGODB AGREGATION PIPELINES --->
An aggregation pipeline in MongoDB is a multi-stage framework that processes, filters, transforms, and analyzes documents sequentially in a collection.

How It Works

• Sequential Stages: Documents pass through an ordered sequence of stages using db.collection.aggregate([stage1, stage2, ...]).
• Step-by-Step Transformation: The output of one stage serves as the input for the next stage.
• Read-Only by Default: It does not modify your original collection unless you include a $merge or $out stage at the end

Core Stages

• $match: Filters documents to pass only those matching specific query conditions.
• $group: Groups documents by a specified key and applies accumulator operators like $sum, $avg, or $push.
• $project: Reshapes documents by adding, removing, or renaming fields.
• $sort: Reorders the incoming documents by specified fields in ascending or descending order.
• $limit / $skip: Restricts or offsets the number of documents passed to the next stage.
• $lookup: Performs a left outer join to a collection in the same database to combine related data.
• $unwind: Deconstructs an array field from the input documents to output a document for each element.

$lookup breif: Performs a left outer join to a collection in the same database to filter in documents from the foreign collection for processing.
 The $lookup stage adds a new array field to each input document. 
The new array field contains the matching documents from the foreign collection.
 The $lookup stage passes these reshaped documents to the next stage.

//WHY WE USE PIPELINES IN PROJECT controller--->

User controller: simple, single-collection queries

Users are usually flat documents (name, email, password hash, role). Typical operations are:

User.findById(id) to fetch a profile
User.findOne({ email }) to log in
User.findByIdAndUpdate(...) to edit a profile

These don’t need a pipeline because the data lives in one collection and goes back as stored.

Project controller: data from multiple collections

Projects tend to be connected to other things: owner, members, tasks, comments, and so on. A project endpoint often needs to:

Join other collections ($lookup), e.g. attach full member details instead of just user IDs
Compute values, e.g. task count, completed percentage, or total budget ($group, $addFields, $size)
Filter or sort on joined or computed data, e.g. “projects where I’m a member, sorted by most active”
Reshape output with $project so the client gets exactly the fields it needs
Paginate a complex result in one database round trip

Browsers send files using multipart/form-data, which is a different format from JSON or normal form data. 
Express’s built-in parsers (express.json() and express.urlencoded()) don’t understand it, so without help, 
req.body would be empty and the file would be lost.
